Planetary Encapsulation — your real location, as a MAC

A 3D-animated human avatar stands inside a transparent capsule shell, feet planted on the planet and the capsule's long axis locked to the local radial — straight out from the Earth's centre through your position. Tap Use my real location and the browser asks for your position (nothing leaves this page); the capsule, the globe avatar above, and the emulated MAC below all move to it together.

Awaiting location
Capsule axis = local vertical · Animation: breathing, arm swing, slow turn

Geolocation needs your permission and a secure context. On a phone it uses GPS / Wi-Fi positioning; on desktop it may be Wi-Fi or IP-based and less precise — the accuracy readout tells you which. If permission is denied or unavailable, the capsule stays on the last position and says so, rather than guessing where you are.

Emulated MAC — derived from this location
02:00:00:00:00:00

A browser cannot read your device's real hardware MAC — so this is an emulated, locally-administered MAC (first byte 02 = locally administered, unicast). It is derived deterministically from your coordinates snapped to a ~11 m grid (0.0001°): the same place always returns the same MAC, and moving to a new grid cell mints a new one. It identifies this capsule at this place, not your hardware.

Ring Bridge — how a ring reading becomes a frame

Same chain as ring_bridge.py, now running live in the browser when you connect above: BLE GATT → 0x2A37 decode → rolling RMSSD → StressProxy → 0x2A19 battery → radio context → fused frame. When live is connected the steps below show the real notifications; otherwise they show the demo values and are labelled demo. The local Python bridge + WebSocket service still runs on your own computer if you prefer that path — this page doesn't replace it.

Ring — BLE GATT notifications

The ring pushes notifications over Bluetooth Low Energy. The bridge holds the one BLE connection (see the notes below).

HeartRateTransducer — 0x2A37 → bpm + RR intervals

Decodes the standard Heart Rate Measurement characteristic: a flags byte, the bpm value, and any RR intervals in units of 1/1024 s.

—
3
HrvTransducer — RR intervals → RMSSD

Rolling RMSSD over the last 60 RR intervals. It needs at least 8 intervals before it reports a value at all.

—
4
StressProxy — bpm + RMSSD → 0…1

0.6 × heart-rate part (bpm above resting 62) + 0.4 × HRV part (RMSSD below baseline 45). A relative-load proxy — not a clinical measure.

—
5
BatteryTransducer — 0x2A19 → percent

Reads the standard Battery Level characteristic as a plain percentage.

—
6
RadioCsvTransducer — newest row of data.csv

Reads the phone's cell log so radio context rides along with the body signals. In this demo it serves the two recorded samples from the Telemetry panel.

—
7
Fusion → TelemetryFrame JSON → WebSocket ingest

Everything merges into one frame, sent to ws://127.0.0.1:8000/ws/telemetry-stream. Frames older than 15 s are not sent — the bridge sends nothing rather than stale values. A REJECTED reply means consent isn't active: grant consent first.

No frame — consent is inactive, so the bridge has nothing to fuse.

Bridge commands (run on your own computer)

python ring_bridge.py scan  ·  python ring_bridge.py inspect  ·  python ring_bridge.py stream [--grant-self]

• Close the vendor app first — most rings accept only one BLE connection at a time.

• Windows / Linux connect by MAC address: 07:32:00:0A:41:79. macOS hides MACs and uses a UUID instead — run scan and put the UUID in the config as the address.

• If inspect shows no standard heart-rate service (0x180D), the ring uses vendor-specific characteristics — add their UUIDs to custom_map in the ring config. This ring's custom_map is currently empty.

• stream --grant-self grants this ring's own consent scopes (heart_rate, device) before streaming; without consent the service replies REJECTED and stores nothing.
